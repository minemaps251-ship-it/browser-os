# План развития BrowserOS: удобное рабочее окружение в браузере

Дата: 21 октября 2026 года. Статус: предложение для последующей реализации.

## Цель

Сделать BrowserOS похожим на целостную операционную систему по поведению: легко
найти приложение и документ, переключиться между задачами, организовать окна,
вернуться к работе после перезагрузки и восстановить ошибочно удалённый файл.
Визуальное направление — macOS, с собственной идентичностью BrowserOS.

Приоритет — завершённые пользовательские сценарии. Кнопка и индикатор появляются
только вместе с работающей функцией. Не имитируем управление Wi-Fi, громкостью
устройства, реальной оперативной памятью и другими недоступными возможностями ОС.

Этот документ дополняет существующий PROJECT_PLAN, не меняя его историю и статусы.
Этап 1 реализован: активные меню приложений, общие команды и сочетания,
оконные кнопки слева, закрепление и перестановка Dock, контекстное меню рабочего
стола, сохранение настроек оболочки, два варианта обоев и справка. Новые команды
публикуют Notes, Code Editor, Files и Terminal; неподдерживаемые меню скрываются.
Поиск и обзор окон остаются следующими этапами. Проверки этапа: 570 unit/integration-тестов, 117 сценариев Chromium и 44 сценария Firefox/WebKit прошли.

Текущее сочетание для нового документа/вкладки — Ctrl+Alt+N; оно распознаётся по
физической клавише и не занимает браузерную команду нового приватного окна.
JSON-экспорт v1 по-прежнему содержит файлы и тему: параметры Dock и обоев в него
не входят, что явно указано в Settings.

## Точка старта

Уже есть общая VFS для Files/Notes/Code Editor/Terminal, IndexedDB, темы,
Dock, управление жизненным циклом приложений и защита несохранённых документов.
Последнее обновление добавило размещение окон на половину и четверть рабочего
стола, предпросмотр и восстановление размера при вытягивании окна.

Основные пробелы по текущему коду:

- Верхняя панель показывает общие элементы, но не команды активного приложения.
- Нет общего поиска и визуального обзора всех окон.
- Files использует одиночное выделение; нет корзины и переноса файлов жестами.
- После перезагрузки сохраняются файлы и тема, но не рабочая раскладка и черновики.
- Настройки покрывают в основном тему, сведения о хранении и экспорт.
- Нет обратного импорта резервной копии.

## Этап 1. Цельная оболочка

### Что изменится

1. Верхняя строка: системное меню BrowserOS, название активного приложения,
   поддерживаемые им меню «Файл», «Правка», «Вид», «Окно», «Справка».
2. Команды соответствуют контексту: «Сохранить» доступно редактору документа,
   «Новая папка» — Files; неподдерживаемые команды не создают ложных ожиданий.
3. Три оконные кнопки слева: закрыть, свернуть, развернуть. Единые размеры,
   подсказки и видимые состояния фокуса; по наведению появляются символы.
   Меню с тремя точками не возвращается.
4. Dock: закрепление, открепление и перестановка приложений; разделение
   закреплённых приложений и остальных запущенных; контекстные действия.
5. Контекстное меню рабочего стола: сменить обои, упорядочить ярлыки,
   открыть настройки. Создание папки на рабочем столе появится вместе с его
   привязкой к VFS на этапе 4.
6. Единые иконки, отступы, состояния наведения, прозрачность и тени.
   Анимации короткие; настройка уменьшения движения сохраняется.
7. Справка по сочетаниям и единая система команд: меню и клавиатура вызывают
   одни и те же действия. Клавиатурные операции учитывают активное приложение,
   модальные окна, ввод текста и IME.

### Готово, когда

- Переключение окна сразу меняет меню активного приложения.
- «Сохранить» через меню и клавиатуру имеет одинаковое поведение и ошибки.
- Изменения Dock сохраняются после перезагрузки.
- Все действия доступны с клавиатуры и через видимые элементы интерфейса.
- Сочетания проверены на macOS и Windows/Linux; системные Cmd+Tab, Cmd+Space
  и браузерные Cmd+W не обещаются как доступные сайту глобальные перехваты.

### Технические границы

Desktop Shell, Window Manager, runtime и настройки. Небольшие типизированные
описания действий и контекст их доступности; без универсальной шины событий.
Для приложения по-прежнему различаем окно и процесс. Перенос кнопок сам по себе
не меняет нынешнюю модель «закрытие последнего окна завершает экземпляр».
Полную модель macOS с работающим без окон приложением обсуждаем отдельно.

Связь с исходным планом: Desktop Shell, M8, клавиатурная доступность.

## Этап 2. Быстрый поиск в духе Spotlight

### Что изменится

- Видимая кнопка поиска в верхней панели и проверенное браузерное сочетание.
- Поиск установленных приложений, сохранённых файлов и доступных команд.
- Группы результатов с иконкой, названием и путём; навигация стрелками,
  открытие Enter, закрытие Escape.
- Повторный выбор уже запущенного singleton-приложения активирует его окно.
- Сначала поиск по именам; содержимое файлов не загружается без необходимости.
- Недавние документы по стабильному ID, с корректной обработкой переименования
  и удаления. Очистка истории доступна пользователю.

### Готово, когда

Пользователь находит файл без открытия Files и запускает приложение без поиска
ярлыка. Устаревший результат не открывает другой документ, устаревший ответ поиска
не заменяет новый. Поиск не читает весь VFS на каждое нажатие клавиши.

Границы: отдельный сервис поиска, registry, VFS и общие действия этапа 1.
Связь с исходным планом: M9 / PALETTE-001; поиск недавних документов — расширение.

## Этап 3. Многозадачность

### Часть 3.1 — обзор и переключение

- Обзор всех окон в духе Mission Control: миниатюры, название приложения,
  выделение текущего окна, переход кликом или клавиатурой.
- Отдельное обозначение свёрнутых окон и возможность восстановить их.
- Быстрое переключение между недавними окнами через браузерно-доступную команду.
- «Показать рабочий стол» с возвратом прежнего расположения окон.
- Миниатюры не создают вторые экземпляры приложений и не запускают их эффекты.

### Часть 3.2 — совместная раскладка

- После размещения окна на половину — ненавязчивое предложение выбрать соседа.
- Общий разделитель двух окон с учётом минимальных размеров обоих приложений.
- Единая команда вернуть окно к свободному расположению.
- Раздельные понятия «заполнить рабочую область» и «полноэкранный режим».
  Полноэкранный режим внутри оболочки скрывает её панели и имеет видимый выход;
  Fullscreen API браузера — отдельное необязательное действие по жесту пользователя.

### Готово, когда

При 6–10 открытых окнах нужное находится без последовательного кликанья по Dock.
Обзор не теряет ввод, курсор редактора и историю отмены. Диалог сохранения нельзя
обойти переключателем. Общий разделитель не уменьшает окна ниже допустимого.

Границы: Window Manager, shell adapters, координация модальных окон.
Связь с исходным планом: развитие раздела 7; новые возможности сверх исходного MVP.

## Этап 4. Files как настоящий файловый менеджер

Реализовать тремя независимыми частями, а не одним переписыванием Files.

### 4.1 — навигация

- Боковая панель: домашняя папка, документы, рабочий стол, недавние и избранное.
- Переходы назад/вперёд, хлебные крошки и ввод пути.
- Список и сетка, сортировка по имени/дате/размеру, поиск внутри каталога.
- Единый диалог выбора файла и места сохранения для Notes и Code Editor.
- Рабочий стол показывает содержимое настоящего каталога VFS, а не второго
  независимого списка файлов. Ярлыки приложений остаются отдельной сущностью.

### 4.2 — выделение и операции

- Множественное выделение с Shift и Ctrl/Cmd, рамка выделения на рабочем столе.
- Копирование, вырезание и вставка файлов внутри BrowserOS.
- Перенос в папку жестом с подсветкой цели и ясной политикой копирования/перемещения.
- Переименование, контекстное меню, свойства файла, «Открыть с помощью».
- Перед переносом нескольких узлов — проверка конфликтов, запрет циклов,
  понятный выбор при совпадении имён. Никаких скрытых частичных успехов.

### 4.3 — корзина

- Обычное удаление из Files перемещает в корзину.
- Восстановление с проверкой прежнего пути, переименованием при конфликте.
- Необратимое удаление и очистка корзины — отдельные явные действия.
- Корзина учитывается в квоте; заполненное хранилище объясняет, что можно освободить.
- Для Terminal заранее определить семантику: `rm` сохраняет явно описанное
  необратимое удаление; перенос в корзину — отдельная команда. Не менять это молча.

### Готово, когда

Файл можно создать на рабочем столе, перенести в Documents, открыть в Notes,
удалить, восстановить и прочитать из Terminal. Все приложения видят один узел,
а ошибка переноса не повреждает дерево и не теряет данные.

Границы: VFS, repository adapters, Files, desktop, file picker.
Сначала операции и тесты домена, затем жесты поверх них. Корзина требует
продуманного изменения схемы и теста миграции существующей IndexedDB.

## Этап 5. Возврат к работе и восстановление данных

### 5.1 — безопасная резервная копия

- Импорт существующего JSON-экспорта с проверкой версии, структуры и квот.
- Предварительный просмотр: число файлов, объём, конфликты и выбранная операция.
- Первая версия — восстановление всего пространства с явным подтверждением,
  предложением скачать текущую копию и защитой открытых несохранённых документов.
- Запись атомарная: ошибка не оставляет наполовину заменённый VFS.
- Слияние нескольких пространств — отдельное последующее расширение.

### 5.2 — восстановление сессии

- Настройка «Открывать прежнее рабочее место».
- Сохранение списка приложений, открытых файлов, положения и размеров окон,
  порядка и закрепления; активные вкладки — где приложение поддерживает контракт.
- При запуске создаются новые процессы из проверенных описаний сессии.
  Удалённые файлы пропускаются с объяснением, координаты подгоняются под экран.
- Снимок записывается после завершения действий с задержкой, а не на каждом pointermove.

### 5.3 — восстановление черновиков

- Черновик хранится отдельно от сохранённого файла, с версией исходного содержимого.
- После сбоя пользователь выбирает восстановить, сравнить или удалить черновик.
- Черновик никогда автоматически не затирает более новую сохранённую версию.
- Сначала автосохранение черновика; автоматическую запись в сам файл обсуждаем
  отдельно с учётом конфликтов и понятной индикации статуса.
- Настройка и очистка черновиков, ограничения объёма, явный статус временного режима.

### Готово, когда

После перезагрузки возвращаются поддерживаемые окна и документы; после аварийного
закрытия доступен недавний черновик. Старая копия или черновик не уничтожает более
новые данные. Сбой импорта оставляет текущее пространство работоспособным.

Границы: session descriptors, document sessions, persistence adapters, boot.
В отличие от текущего поведения это сознательное расширение правил восстановления.
Хранение остаётся локальным: восстановление сессии не означает облачную синхронизацию.

## Этап 6. Настройки и системная обратная связь

- Настройки с разделами: оформление, Dock, окна, клавиатура, хранение, восстановление.
- Выбор встроенных обоев, акцентного цвета, масштаба интерфейса и языка RU/EN.
  Сначала завести переводы общих системных строк, затем переводить приложения.
- Компактная панель быстрых настроек с реально работающими функциями.
- Часы открывают календарь; быстрые действия ведут в соответствующий раздел настроек.
- Уведомления о длительных завершённых операциях и проблемах, требующих действия;
  обычное сохранение не создаёт поток всплывающих сообщений.
- Центр уведомлений с ограниченной историей, очисткой и режимом «Не беспокоить»;
  критические ошибки сохранения остаются видны в приложении.
- Диспетчер приложений: запущенные экземпляры, состояние, переход к окну,
  корректное закрытие и перезапуск после сбоя. Без выдуманных процентов CPU/RAM.

Готово, когда настройки сохраняются, изменения отражаются во всём окружении,
а одно событие не дублируется в диалоге и нескольких уведомлениях.
Связь с исходным планом: M8, TASK-001, NOTIFY-001.

## Этап 7. Продвинутые возможности

После завершения основных сценариев:

1. Несколько рабочих столов: создание, переключение, перенос окон через обзор,
   явная политика поведения Dock и безопасный перенос при удалении стола.
2. Изображения и другие бинарные файлы: сначала расширить VFS, квоты, экспорт
   и импорт, затем добавлять просмотрщик и безопасный предпросмотр.
3. Импорт и скачивание обычных файлов пользователя; разрешения и форматы объяснять
   перед операцией. Неподдерживаемые файлы не выдавать за успешно открытые.
4. Установка как PWA и офлайн-режим: политика обновления не перезагружает рабочее
   место с несохранённым вводом; проверка поведения в поддерживаемых браузерах.
5. Калькулятор и другие небольшие приложения, если они завершают реальные задачи.

Аккаунты, облачная синхронизация, сторонние плагины и произвольное выполнение кода
не входят в ближайшую очередь: это отдельные продукты и модели безопасности.

## Сквозные требования

- Сохранять разделение Window Manager, runtime, VFS, persistence и React adapters.
- Не расширять один глобальный Zustand store всем новым состоянием.
- Для каждого этапа — отдельный ExecPlan при существенных изменениях, небольшие
  проверяемые части и отсутствие несвязанных переписываний.
- Unit-тесты домена, integration-тесты взаимодействий, Playwright критических сценариев.
- Lint, typecheck, тесты и сборка перед публикацией; целевые проверки Firefox/WebKit
  для изменений жестов, клавиатуры, хранения и полноэкранного режима.
- Проверять масштаб 200%, клавиатуру, возврат фокуса, reduced motion, контраст,
  IME, небольшой экран и настоящее сенсорное устройство для заявленной поддержки.
- Не монтировать вторые копии приложений ради превью, не писать IndexedDB на каждом
  движении мыши; сравнивать отзывчивость с текущей версией на сценарии десяти окон.
- Для миграций — тесты на существующем формате данных и на отмене транзакции.
- Каждая публикация — проверка публичного демо и краткая запись результата.

## Предлагаемый первый выпуск

Начать с этапа 1: верхняя панель активного приложения, общий механизм действий,
кнопки окна слева и настраиваемый Dock. Затем отдельным выпуском добавить поиск
этапа 2, после него обзор окон этапа 3.1. Это даст заметное ощущение ОС до больших
изменений Files и хранения. Части этапа 5 выполнять по отдельности; приоритет
повышать, если окружение начинает использоваться для важных реальных документов.

Первый контрольный сценарий: открыть Notes из Dock → создать документ → сохранить
через меню → открыть Terminal → вернуться к Notes через переключение окон →
найти документ через поиск → открыть его без потери состояния приложения.
